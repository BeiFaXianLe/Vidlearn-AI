## 二、S0-02 平台字幕：**部分通过（有严重不稳定问题）**

### 2.1 基本能力
```
GET /x/player/v2?aid=...&cid=...
→ subtitle.subtitles = [{lan: "ai-zh", lan_doc: "中文", ai_type: 0, subtitle_url: "//aisubtitle.hdslb.com/..."}]
```
- ✅ 能拿到字幕轨道列表
- ✅ 能区分 AI 字幕（`ai_type=0`）——满足 PRD「人工/AI 不得混淆」
- ✅ 能下载字幕 JSON 体（`body[]`，字段 `from`/`to` 单位为**秒**，需 ×1000 转毫秒）

### 2.2 严重问题：同一请求返回不一致（A 级证据）

连续 3 次请求同一 `aid+cid`：

| 次数 | 条数 | 时间范围 | 判定 |
|---|---|---|---|
| 1 | 55 | 0.00 – 105.36s | ✅ 与视频时长 106s 一致 |
| 2 | 138 | 2.18 – 306.12s | ❌ **超出视频时长 3 倍** |
| 3 | 55 | 0.00 – 105.36s | ✅ 一致 |

另有一轮拿到 173 条、末条 309.02s（同样错位）。

**结论：B站 AI 字幕接口存在"污染返回"**——同一 cid 有时返回明显不属于该视频的字幕体（条数与时长均不符）。盲信会生成错误总结。

### 2.3 由此产生的强制实现约束（写入 S3/S4）

1. **字幕时间戳必须与媒体时长强校验**：`末条.to ≤ duration + 容差(2s)`，超出则丢弃重取。
2. **重取策略**：失败重试 N 次（建议 3），全部失败则该轨道标记 `invalid`，降级到内嵌字幕/ASR。
3. **不允许只取最后一次结果**：应取多次中"时间戳合理"的那一份。
4. **auth_key 时效**：`subtitle_url` 带 `auth_key`，重复使用可能返回空 → 每次取字幕应重新请求 `/x/player/v2` 拿新 URL。
5. **cid 权威来源**：用 `/x/web-interface/view` 的 `data.cid`（不是从 yt-dlp 输出推断）。

### 2.4 与匿名对比

|---|---|
| 匿名 | 0 |
| 登录态 | 有（1 条 ai-zh 轨道） |

→ **证实 V2.0 的「平台字幕优先」策略成立，但前提是登录态 + 强校验。**

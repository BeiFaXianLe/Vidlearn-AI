## 1. 产品概述

### 1.1 产品定位

VidLearn AI 是一个面向视频学习场景的 AI 视频理解与知识管理工具。

用户输入在线视频地址或导入本地视频，系统自动完成视频获取、字幕提取、语音识别、AI 内容理解和知识整理，最终将视频转换为可播放、可检索、可交互的学习资料。

产品核心理念：

**不只是总结视频，而是将视频转化为可持续使用的知识资产。**

### 1.2 核心用户价值

1. 不必完整观看长视频，也能快速掌握核心内容。
2. 能够按照章节和知识点定位视频原始位置。
3. 可以围绕视频内容与 AI 进行问答。
4. 可以保存笔记、学习进度和重要知识点。
5. 视频及其知识资料保存在本地，形成个人视频知识库。

### 1.3 产品目标

V2.0 的目标是建立一个完整、可运行的 Windows 本地视频学习系统。

重点解决四个问题：

- 视频能否稳定获取。
- 字幕能否可靠获取。
- AI 能否准确理解视频内容。
- 用户能否围绕视频完成学习和知识沉淀。

## 2. 用户使用流程

### 核心业务流程

1. **导入视频**
   支持 Bilibili、抖音和本地视频文件。
2. **下载与媒体校验**
   获取视频文件，检查文件完整性、编码和可播放性。
3. **字幕获取**
   优先使用平台字幕，其次提取内嵌字幕，最后使用本地 ASR。
4. **AI 内容分析**
   生成摘要、章节、知识点、关键时间戳。
5. **保存学习资料**
   保存视频、字幕、分析结果及用户笔记。
6. **进入学习工作台**
   播放视频、同步字幕、跳转章节、AI 问答和记录学习进度。

## 3. 功能需求

### 3.1 视频导入模块

| 功能 | 需求说明 | 优先级 |
|--------|--------|--------|
| B站链接导入 | 支持匿名和登录态下载 | P0 |
| B站 Cookie 导入 | 手动粘贴 Cookie | P0 |
| B站视频下载 | 登录态优先获取 1080P，匿名模式按 720P 处理 | P0 |
| B站字幕 | 获取平台人工字幕及 AI 字幕 | P0 |
| 抖音链接导入 | 通过独立下载器处理 | P0 |
| 本地视频导入 | 支持选择本地视频文件 | P0 |
| 批量导入 | 支持多视频任务 | P1 |
| 重复检测 | 根据来源标识及文件信息去重 | P1 |

说明：平台提供的清晰度和字幕能力可能受账号权限、视频版权、地区、平台接口变化等因素影响，不能保证每条视频都能获取到 1080P 或平台字幕。

### 3.2 凭证管理模块

**B站 Cookie 管理**

- 用户手动粘贴 Cookie。
- 系统转换为下载工具所需格式。
- 使用 Windows DPAPI 加密保存。
- 不在普通日志中输出 Cookie。
- 支持更新、清除和失效检测。
- Cookie 不进入代码仓库和普通临时文件。

**安全要求**

- 凭证只用于本地下载流程。
- 不向 AI 服务提供 Cookie。
- 不向外部服务传输凭证。
- 不在异常堆栈和调试日志中暴露凭证。

### 3.3 抖音下载模块

采用 `jiji262/douyin-downloader` 作为首选技术方案。

架构要求：

- 独立 Python 子进程。
- 与主业务进程隔离。
- 使用统一的 DouyinAdapter 接口。
- 主程序通过标准输入输出或约定的进程通信协议获取结果。
- 下载失败时返回明确错误码。
- 支持后续替换其他下载实现。

D05 PoC 验证内容：

1. 短链接解析。
2. 长链接解析。
3. 视频元数据获取。
4. 实际视频下载。
5. FFprobe 文件验证。
6. 匿名模式测试。
7. Cookie 必要性测试。
8. 项目依赖、许可证和运行稳定性检查。

（上线门禁）PoC 不通过，不得将抖音下载能力标记为正式可用。

### 3.4 字幕处理模块

字幕获取优先级：

| 顺序 | 字幕来源 | 说明 |
|--------|--------|--------|
| 1 | 平台字幕 | B站登录态平台字幕优先 |
| 2 | 内嵌字幕 | 从视频文件中提取 |
| 3 | 本地 ASR | faster-whisper |
| 4 | 云端 ASR | 可选扩展，不作为默认流程 |

字幕数据必须保留：

- 字幕内容。
- 开始时间。
- 结束时间。
- 语言。
- 字幕来源。
- 字幕质量或状态。

平台字幕需要区分人工字幕和 AI 字幕，不得将两者混为同一来源。

### 3.5 本地 ASR 模块

默认采用 faster-whisper。

处理流程：

```text
视频文件
   ↓
FFmpeg 提取音频
   ↓
16kHz 单声道 PCM
   ↓
faster-whisper
   ↓
字幕分段
   ↓
时间戳归一化
   ↓
保存 transcript_segments
```

关键技术约束：

- 不使用 PyAV 作为音频处理的核心路径。
- 使用 FFmpeg 完成音频提取。
- ASR 默认采用本地模型。
- 支持长视频分段处理。
- 支持分段结果合并。
- 记录模型、语言和识别状态。

### 3.6 AI 视频分析模块

输入数据为字幕文本及必要的时间戳信息。

输出内容：

| 功能 | 说明 |
|--------|--------|
| 视频摘要 | 提炼核心内容 |
| 章节划分 | 按内容逻辑生成章节 |
| 知识点提取 | 提取重要概念和结论 |
| 关键时间戳 | 关联原始视频位置 |
| 视频问答 | 基于字幕和分析结果回答 |
| 知识整理 | 形成可持续保存的学习资料 |

云端 AI 数据边界：

（已冻结）仅上传文本类数据。

禁止上传：

- 原始视频。
- 原始音频。
- 视频关键帧。
- 未经用户授权的其他媒体内容。

### 3.7 视频学习工作台

保留既有原型中的核心交互能力：

- 视频播放器。
- 字幕同步。
- 章节目录。
- 章节跳转。
- AI 摘要。
- 知识点展示。
- AI 问答。
- 学习笔记。
- 学习进度。
- 历史学习记录。

### 3.8 视频库

视频库作为用户的长期知识资产入口。

主要功能：

- 视频列表。
- 视频详情。
- 视频封面。
- 来源信息。
- 处理状态。
- 学习进度。
- 搜索和筛选。
- 删除视频。

视频默认永久保留，只有用户主动删除时才执行清理。

删除操作需要明确区分：

1. 删除学习资料。
2. 删除视频文件。
3. 同时删除视频及其关联资料。

具体交互和关联清理策略在 S7 阶段冻结。

## 4. 数据模型要求

V2.0 继续保留现有核心数据模型：

| 数据模型 | 职责 |
|--------|--------|
| `media_assets` | 视频媒体资产及文件信息 |
| `source_captions` | 原始字幕来源及内容 |
| `transcript_segments` | 标准化字幕分段 |

媒体完整性状态至少支持：

- `verified`
- `likely`
- `partial`
- `unknown`

任务状态：

```text
CREATED
   ↓
MEDIA_PROCESSING
   ↓
MEDIA_READY
   ↓
TRANSCRIPT_PROCESSING
   ↓
TRANSCRIPT_READY
   ↓
AI_ANALYZING
   ↓
COMPLETED / FAILED
```

不得因为某一个 FFprobe 指标异常，就简单认定文件一定不可用；需要结合文件大小、容器解析、时长、音视频流和实际播放验证。

## 5. 非功能需求

| 维度 | 要求 |
|--------|--------|
| 操作系统 | Windows 优先 |
| 本地运行 | 视频处理和 ASR 在本地执行 |
| 媒体处理 | FFmpeg / FFprobe |
| 视频编码 | 优先兼容 H.264 |
| 长视频 | 支持分段处理和任务恢复 |
| 安全 | Cookie 加密、日志脱敏 |
| 稳定性 | 下载失败、识别失败、AI 失败可独立恢复 |
| 数据持久化 | 视频长期保留 |
| 可扩展性 | 下载器、ASR、LLM 使用 Provider/Adapter 抽象 |

## 6. 验收标准

| 模块 | 验收条件 |
|--------|--------|
| B站匿名 | 能下载符合权限范围的视频 |
| B站登录 | 手动 Cookie 可导入、加密和使用 |
| B站字幕 | 能获取可用的平台字幕；缺失时进入后续流程 |
| 抖音 | PoC 通过后，完成真实视频下载和媒体校验 |
| 本地导入 | 可导入本地视频并进入处理流程 |
| 字幕 | 能正确提取、识别、保存和同步 |
| AI 分析 | 能生成摘要、章节、知识点 |
| 播放器 | 支持本地视频播放和时间戳跳转 |
| 知识库 | 可保存、检索和再次打开学习资料 |
| 安全 | Cookie 不明文存储、不输出到日志 |
| 长期存储 | 重启后视频和学习资料仍然存在 |

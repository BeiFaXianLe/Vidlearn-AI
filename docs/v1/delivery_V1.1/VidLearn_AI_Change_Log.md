# VidLearn AI V1.0 → V1.1 变更清单

## 一句话概括
页面原型保持不变，处理内核从“平台链接直接找字幕/文本”调整为“网络或本地媒体统一进入本地媒体库，再通过 FFmpeg、字幕优先和云端 ASR 完成内容加工”。

## 1. 功能与流程变化

| 模块 | 原版 | 调整版 | 影响 |
|---|---|---|---|
| 输入 | 主要粘贴 B站/抖音 URL | URL + 本地视频/音频/字幕 | 新增本地文件入口 |
| 网络解析 | Adapter 获取元数据/字幕 | Adapter + yt-dlp 获取元数据、字幕、媒体 | 新增下载子任务 |
| 媒体处理 | 非主流程 | FFmpeg/FFprobe 标准化处理 | 新增媒体处理引擎 |
| 媒体存储 | 不默认保存视频 | 默认本地媒体库保留，可选择处理后删除 | 新增存储配额和清理 |
| 字幕策略 | 平台字幕优先，缺失则 ASR | 平台字幕/内嵌字幕/用户字幕优先，缺失或不完整则 ASR | 增加内嵌字幕提取 |
| 播放 | 官方嵌入优先 | 本地视频播放优先；无法本地播放才嵌入/跳转 | 播放源逻辑变化，布局不变 |
| 总结 | 有文本即可生成 | 先检查完整性，完整/部分范围分开标记 | 防止误报完整总结 |
| 数据库 | 视频、字幕、总结、任务等 | 新增 media_assets、source_captions | 迁移和文件元数据管理 |
| 任务系统 | 解析/转写/总结 | 下载/上传/探测/字幕/提取音频/ASR/完整性/总结/清理 | 任务粒度更细 |
| 安全 | URL、API Key 等 | 额外覆盖文件上传、子进程、路径、磁盘和媒体访问 | 安全测试扩展 |
| 成本 | ASR/LLM 为主 | 增加下载带宽、磁盘和 ASR 成本控制 | 新增存储指标 |

## 2. 不变的内容
- 已确认的 HTML 原型视觉布局和详情页 Tab 结构。
- 产品定位：把视频变成可搜索、可复习的知识资产。
- 一期平台重点：Bilibili、抖音。
- ASR 和 LLM 全部云端。
- SQLite 作为一期本地数据库。
- 快速总结、深度学习总结、章节、知识点、笔记。
- 不绕过平台登录、会员、DRM、反爬或访问控制。

## 3. 新增必须建设的能力
1. yt-dlp 封装与版本固定。
2. FFmpeg/FFprobe 封装。
3. 本地视频/音频/字幕上传。
4. media_assets 文件元数据、SHA256 去重。
5. 正式媒体库、临时区、ASR 音频工作区。
6. 原始字幕来源保存和标准化。
7. 媒体/字幕完整性检测。
8. 文件保留策略、临时文件 TTL、磁盘空间管理。
9. 本地媒体 Range 播放接口。
10. 更全面的文件与子进程安全控制。

## 4. 一期建议优先级
- P0：本地文件上传、媒体探测、字幕轨道提取、ASR、总结、章节、学习工作台。
- P0：网络获取先针对经过验证的 B站/抖音 URL 类型试点；不能稳定获取的平台保留失败降级。
- P1：关键帧多模态理解、双语字幕、目录监听、NAS/对象存储、跨视频 RAG。

## 5. 风险重新排序
1. 平台下载能力会随页面/API变化，不能承诺全量支持。
2. 下载权限与版权边界必须明确。
3. 视频文件会快速占用磁盘，必须做限额和清理。
4. FFmpeg/yt-dlp 子进程必须安全隔离。
5. 长音频 ASR 费用和供应商限制需要切片与成本保护。
6. 多来源字幕的时间戳和完整性需要校验。
7. FFmpeg 构建选项可能影响许可证义务，发布前需要审核。

## 6. 需要在 S0 冻结的决策
- B站/抖音哪些 URL 类型可以稳定、合规地取得完整媒体。
- yt-dlp 固定版本与升级策略。
- FFmpeg 构建选项与发布许可证策略。
- 默认媒体保留策略和存储配额。
- 首选云端 ASR 服务商及单文件长度/费用限制。
- “完整/大概率完整/部分/未知”的判定阈值。

# VidLearn AI 开发计划（媒体下载与本地处理流程调整版 V1.1）

> 页面原型不做视觉改版。本计划将工程重点从“平台链接 → 文本”调整为“网络/本地媒体 → 本地媒体资产 → 字幕/ASR → AI 学习内容”。  
> S0 必须先验证 yt-dlp、FFmpeg、B站/抖音真实能力和许可，不允许先承诺全站下载。

## 1. 本次开发计划变化

| 项目 | V1.0 计划 | V1.1 调整 |
|---|---|---|
| 输入入口 | 主要是视频 URL | URL + 本地视频/音频/字幕 |
| 网络获取 | 平台 Adapter 直接取元数据/字幕 | Adapter 包装 yt-dlp，负责元数据、字幕和媒体获取 |
| 媒体处理 | 非核心 | 新增 FFprobe/FFmpeg 媒体处理模块 |
| 视频存储 | 不默认保存视频 | 默认本地媒体库保留，可按视频清理 |
| 字幕 | 平台字幕 → ASR | 平台字幕/内嵌字幕优先 → ASR 兜底 |
| 播放 | 官方嵌入优先 | 本地媒体播放优先，平台嵌入/跳转作为降级 |
| 完整性 | 任务成功/失败 | 增加媒体、字幕、内容范围完整性状态 |
| 数据模型 | 视频、转写、总结等 | 新增 media_assets、source_captions 等媒体资产表 |
| 风险重点 | 平台解析可用性 | 下载权限、文件安全、存储、子进程、完整性、平台可用性 |

## 2. 里程碑与预计周期

| 阶段 | 目标 | 预估工作日 | 主要交付 |
|---|---|---:|---|
| S0 | 源码尽调与媒体工具/平台可行性验证 | 4–6 | REPO_COMPARISON、MEDIA_TOOL_VALIDATION、决策记录 |
| S1 | 工程骨架、数据库、文件存储、Worker | 4–6 | 可运行工程、媒体表、任务状态机 |
| S2 | 网络下载与本地上传 | 5–8 | yt-dlp Adapter、B站/抖音试点、本地文件上传 |
| S3 | FFmpeg 媒体处理与字幕获取 | 4–7 | FFprobe、字幕抽取、音频提取、哈希校验 |
| S4 | ASR 与完整性判断 | 4–7 | 分段 ASR、时间轴合并、完整/部分判定 |
| S5 | AI 总结、章节和知识点 | 5–8 | 快速/深度总结、结构化知识产物 |
| S6 | 首页和学习工作台接入真实数据 | 5–8 | 沿用现有视觉原型，接入本地播放和字幕 |
| S7 | 文件保留策略、导出和知识管理 | 3–6 | 清理任务、备份、Markdown 导出 |
| S8 | 安全、性能、E2E 与发布 | 5–8 | 验收报告、部署说明、Release Candidate |

**粗略总计：39–64 个工作日**（单人主开发、Harness 辅助；S0 结果可能改变网络下载范围）。若需要大文件断点上传、复杂多模态和 NAS，另列后续版本。

### S2 — 网络媒体获取与本地上传（P0）

- [ ] S2-05 实现 Bilibili Adapter，仅使用 S0 验证通过且用户有权获取的方式。

## 5. Harness 每个任务执行规约
1. 开始前读取项目说明和相关代码。
2. 先报告计划、拟修改文件和风险。
3. 不得伪造平台支持情况、下载成功、视频完整性或测试结果。
4. 不得引入 Cookie、会员绕过、DRM 绕过或反爬规避逻辑。
5. 对 yt-dlp/FFmpeg 调用必须参数化、安全隔离并有超时/资源限制。
6. 小步修改，执行单测、集成测试和必要的 E2E。
7. 汇报改动、命令、测试输出、未验证事项和剩余风险。

## 6. Definition of Done
- URL 与本地文件进入同一套媒体资产和处理模型。
- 下载/上传文件经 FFprobe 验证后才进入正式媒体库。
- 字幕优先，ASR 兜底，时间戳正确映射。
- 总结完整性与内容覆盖范围一致。
- 本地播放器、字幕瀑布流和章节定位可用。
- 媒体保留/删除策略有效，临时资源可清理。
- 下载器和媒体处理进程受到安全限制。
- 平台能力边界和许可证审查已形成文档。

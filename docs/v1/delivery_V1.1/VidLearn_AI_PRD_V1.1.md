# VidLearn AI 产品需求文档（处理流程调整版 V1.1）

> 状态：产品基线候选版。页面原型与信息架构保持 V1.0；本次重点调整媒体获取、文件管理、字幕与 AI 处理流水线。  
> 产品定位：以本地媒体库为基础的个人视频学习与知识沉淀平台。  
> 一期来源：Bilibili、抖音网络链接 + 用户本地视频/音频/字幕文件。  
> 核心技术：yt-dlp（网络媒体获取适配器）、FFmpeg/FFprobe（统一媒体处理）、云端 ASR、云端 LLM。

---

## 1. 本次调整结论

### 1.1 核心决策
VidLearn AI 不再把“直接从平台取得字幕”作为唯一内容入口。统一调整为：

**网络链接 / 本地文件 → 本地媒体资产 → 媒体探测与处理 → 原始字幕优先 → 云端 ASR 兜底 → 完整性检查 → AI 总结与知识提取。**

- 网络链接：通过平台 Adapter 调用 yt-dlp 等适配工具，在用户有权获取且工具可正常访问时取得媒体文件和字幕。
- 本地文件：用户上传视频、音频或字幕文件，直接进入同一处理管线。
- 字幕：优先使用可获取的平台字幕或视频内嵌字幕轨道；缺失、不完整或质量不合格时，提取音频走云端 ASR。
- 视频文件：默认纳入 VidLearn AI 本地媒体库，供本地播放、复习和后续多模态处理；用户可以按视频选择处理后删除。
- AI：只对通过完整性检查的内容生成“完整总结”；内容不完整时必须标记为“部分内容总结”或要求补充素材。

### 1.2 本次不变的内容
- 高保真 HTML 原型、首页布局、卡片、详情页左右分栏和右侧 AI 总结/章节/字幕/笔记 Tab 不做视觉改版。
- B站与抖音仍是一期优先平台。
- ASR 与 LLM 仍然全部使用云端服务。
- SQLite 仍作为一期本地数据持久化方案。
- 原型中的模拟数据和按钮仍然仅用于交互展示，不代表平台接入已完成。

### 1.3 本次发生变化的内容
1. 下载/上传媒体成为一等输入入口，不再只导入平台 URL。
2. yt-dlp 和 FFmpeg/FFprobe 进入核心处理架构。
3. 媒体文件默认保存到本地媒体库，提供保留策略。
4. 字幕获取变成“平台字幕/内嵌字幕优先，ASR 兜底”。
5. 新增媒体文件校验、去重、完整性检查、磁盘空间和清理任务。
6. 播放器区域优先播放本地媒体；本地媒体不可用时才使用官方嵌入或原平台跳转。
7. 增加完整内容/部分内容状态，防止把试看或截断素材误标为完整总结。

## 2. 产品定位与目标

### 2.1 产品定位
将用户有权获取或自行提供的视频内容，统一转化为可观看、可检索、可复习的知识资产。产品不是单纯下载器、字幕翻译工具，也不是绕过平台访问限制的工具。

### 2.2 一期核心目标
- 用户可以导入 B站/抖音链接，也可以上传本地视频、音频和字幕文件。
- 对合法可获取的网络视频，尝试下载完整媒体文件并保存至本地媒体库。
- 使用 FFprobe 识别时长、编码、流信息；FFmpeg 提取音频、字幕轨道和关键帧。
- 尽可能先获得原始字幕，减少 ASR 成本；字幕不可用或不完整时调用云端 ASR。
- 对转写内容进行完整性检测，明确区分完整、部分和未知。
- 生成快速总结、深度学习总结、章节、知识点和时间戳。
- 在统一学习工作台中本地播放视频、展示字幕瀑布流、AI 总结和笔记。

### 2.3 不承诺的能力
- 不承诺 yt-dlp 支持的所有站点、所有链接和所有视频永久可用。
- 不承诺所有公开视频都允许下载或处理。
- 不绕过 DRM、会员、登录墙、付费内容、反爬、验证码或其他访问控制。
- 不将用户浏览器 Cookie、平台登录态或账号凭证交给下载器。
- 不承诺损坏、加密、未知编码或不受支持的媒体文件都能解析。
- 不在没有完整字幕/音频证据时生成“完整总结”。

## 3. 用户与使用场景

主要用户：需要从技术视频、课程录播、会议录像、公开教程和短视频中持续学习的开发者与知识工作者。

场景：
1. 粘贴 B站或抖音视频链接，创建网络媒体获取任务。
2. 上传自己已有的视频、音频或字幕文件。
3. 下载/导入完成后自动探测媒体，提取字幕。
4. 没有可用字幕时，由云端 ASR 转写。
5. 查看完整字幕、章节和深度总结。
6. 在详情页本地播放原视频，点击字幕或章节定位。
7. 保留视频长期复习，或在处理完毕后删除原媒体、只保留知识资产。

## 4. 输入来源与处理边界

### 4.1 网络链接
一期重点：
- Bilibili：支持范围以 yt-dlp 对公开且用户有权获取的视频的实际验证为准。
- 抖音：支持范围以公开分享链接和实际验证为准；短链解析、视频获取和字幕能力分别判定。
- 其他网站：架构预留通用 yt-dlp Adapter，但不作为一期 SLA 承诺。

处理原则：
- 先校验 URL、协议、DNS 和重定向。
- 识别平台后调用对应 Adapter。
- 元数据、字幕与媒体文件获取可以作为独立子任务。
- 若无法合法、稳定获取媒体文件，保留视频条目并说明原因；允许用户自行提供有权使用的本地文件。
- 禁止通过注入账号 Cookie、绕过访问控制或规避 DRM 达成下载。

### 4.2 本地文件
支持常见媒体容器与编码，最终能力取决于当前 FFmpeg 构建：
- 视频：MP4、MOV、MKV、WebM、AVI 等常见格式。
- 音频：MP3、M4A、AAC、WAV、FLAC 等常见格式。
- 字幕：SRT、VTT、ASS/SSA、LRC（按解析支持范围）。
- 用户上传视频/音频可进入完整 ASR 流程；单独上传字幕可直接进入文本清洗与 AI 处理。

一期通过 Web 上传导入；后续可增加本地监听目录，不允许前端任意提交服务器文件系统路径。

### 4.3 媒体权限与责任边界
用户必须确认其对待导入内容具备相应的访问和处理权限。工具可用性不等于下载或再利用授权。系统不提供访问控制绕过能力。用户上传的文件仅用于该用户的处理请求，需明确云端 ASR/LLM 会接收哪些音频/文本内容。

## 5. 核心流程

### 5.1 网络链接导入流程

```text
粘贴 URL
  ↓
URL 安全校验 + 平台识别
  ↓
获取元数据（标题、作者、时长、封面、平台 ID）
  ↓
并行尝试获取可用字幕 + 获取媒体文件
  ↓
媒体文件落入临时区
  ↓
FFprobe 探测 + 文件完整性/时长校验 + SHA256 去重
  ↓
通过校验 → 移入正式媒体库（默认保留）
  ↓
字幕策略：平台字幕 / 字幕轨道优先
  ↓
字幕完整性检查
  ├─ 完整且质量合格 → 标准化字幕
  └─ 缺失/部分/质量不合格 → FFmpeg 提取音频 → 云端 ASR
  ↓
字幕与媒体时长对齐检查
  ↓
快速总结 → 深度总结 → 章节 → 知识点
  ↓
完成；记录媒体保留策略和处理成本
```

下载失败但字幕获取成功时：可以创建“文本可学习”状态并生成有边界的总结；不能假设有本地完整视频可播放。媒体获取失败且字幕也未取得时，显示待用户补充文件。

### 5.2 本地视频导入流程

```text
上传视频/音频/字幕
  ↓
文件类型、大小、扩展名与实际 MIME/文件头校验
  ↓
隔离临时目录 + 病毒/异常文件策略（按部署条件）
  ↓
FFprobe 识别媒体流和时长
  ↓
生成媒体资产记录、SHA256 去重
  ↓
有内嵌字幕轨道 → 提取字幕
无字幕 / 字幕不完整 → 提取音频 → 云端 ASR
  ↓
字幕完整性检查
  ↓
AI 总结、章节、知识点
  ↓
媒体进入长期保留库或按策略清理
```

若用户只上传 SRT/VTT 等字幕文件，则跳过媒体探测和 ASR，直接进入字幕校验与 AI 内容处理。

### 5.3 字幕获取优先级
1. 平台人工字幕（可获得且来源可信）。
2. 平台自动字幕（记录其为平台自动生成）。
3. 视频内嵌字幕轨道（FFmpeg 可提取时）。
4. 用户上传字幕文件。
5. 云端 ASR（无字幕或字幕不完整时）。

说明：
- 不同来源的字幕分别保存原始文件/原始文本，不相互覆盖。
- 可以选择可信度较高的字幕作为主字幕；其余作为备选来源。
- ASR 应只补足缺失片段或重做低质量字幕，避免不必要的重复费用。
- 字幕润色、翻译或术语修正必须保存为派生版本，不能覆盖原始字幕。

### 5.4 ASR 音频处理
- 使用 FFmpeg 从媒体中提取 ASR 服务要求的音频格式。
- 按供应商限制进行切片，保留每片起止时间和全局偏移。
- 分片之间可设置少量重叠，合并时去除重复文本。
- 每段 ASR 结果保留时间戳、语言、置信度（服务商提供时）和 Provider 信息。
- 处理成功后可删除临时音频；原视频按用户保留策略处理。
- 必须实现超时、限流、重试、并发控制、费用预估/统计。

### 5.5 内容完整性检查
为视频和字幕分别计算状态：
- `media_status`: downloaded / uploaded / unavailable / failed / invalid。
- `transcript_status`: complete / partial / missing / unknown / failed。
- `content_scope`: full / partial / unknown。

完整性检查参考：
- 媒体时长与元数据时长是否大致一致。
- 文件探测是否存在有效视频/音频流，解码是否可持续到尾部。
- 字幕/ASR 时间戳是否落在有效时长范围。
- 字幕首尾时间覆盖是否合理。
- 是否存在异常长时间空白、截断或缺片。
- 原始字幕是否只覆盖试看片段。
- 不能仅凭“字幕条数很多”判定完整。

阈值应可配置，不同视频类型可能存在大量静音。检测结果使用“已验证完整 / 大概率完整 / 部分内容 / 未知”而非单一伪精确百分比。用户可查看检测依据。只有可信的完整内容才允许标记完整总结；其余总结必须注明覆盖区间与不完整风险。

## 6. 页面与交互规格（视觉结构不变）

### 6.1 视频首页
保留现有原型：
- 顶部导入入口。
- 数据概览、继续学习、视频卡片、搜索与筛选。
- 视频卡片显示来源平台、时长、媒体状态、字幕状态、AI 处理状态。
- 后续在现有导入入口内支持“粘贴链接 / 上传本地文件 / 导入字幕文件”，不改动首页整体布局。

### 6.2 视频详情学习工作台
沿用当前原型左右分栏：
- 左侧播放器区域：优先播放本地媒体库中的视频文件；没有本地媒体时尝试官方嵌入；仍不可用则提供原平台跳转。
- 右侧默认 AI 总结，可切换章节、字幕、笔记。
- 本地播放器的播放时间与字幕时间戳统一用毫秒/PTS 映射，点击字幕和章节定位本地视频。
- 播放器不可用时仍可阅读已有总结、字幕和笔记。

### 6.3 AI 总结
快速总结：
- 一句话概括。
- 3–7 个核心要点。
- 关键术语。
- 适合谁看/是否值得深入。
- 内容范围标记：完整或部分。

深度学习总结（技术类）：
- 问题背景与目标。
- 核心原理、机制和组件关系。
- 实现步骤与操作流程。
- 代码、SQL、命令、配置和关键参数。
- 应用场景、边界条件、坑点。
- 优缺点、替代方案。
- 实践清单、验证方法和后续学习主题。

非技术类：
- 主题结论、核心观点、论据/案例、方法步骤、适用条件、行动项。

多模态增强：
- P1 支持抽取关键帧，识别代码、架构图、表格、终端输出和演示画面。
- 图片与总结中的相关段落建立时间关联。
- 无图像模型能力时，以文本转写总结为基础，并明确无法理解画面内容。

### 6.4 章节、字幕和笔记
- 字幕瀑布流展示标准化分段，按时间排序，支持搜索与复制。
- 章节有起止时间、标题、摘要和时间戳来源。
- 点击字幕/章节可定位本地播放器；只有可信时间戳允许精确跳转。
- 笔记可关联视频时间点、章节或字幕片段。
- 导出 Markdown 保留原始来源 URL、媒体文件名、时间戳与生成信息。

## 7. 媒体文件管理与存储策略

### 7.1 默认策略
- 默认：处理完成后保留原始媒体文件在本地媒体库，以支持本地播放和后续复习。
- 用户可按视频设置“长期保留”或“处理完成后删除媒体，仅保留知识资产”。
- 临时下载文件和 ASR 音频切片应设置 TTL，并在失败/取消时清理。
- 用户删除视频时，提供“同时删除媒体文件 / 仅删除索引 / 保留总结笔记”等明确选项。

### 7.2 存储目录建议
```text
data/
  database/                 # SQLite 数据库
  media/
    original/               # 已验证的原始视频/音频
    temp/                   # 下载和上传暂存
    audio_work/             # ASR 临时切片
    subtitles/              # 原始字幕文件
    thumbnails/             # 封面/缩略图
    keyframes/              # P1 关键帧
  exports/                  # Markdown 等导出
  logs/
```

### 7.3 资源管理
- 保存文件相对路径，不在数据库保存媒体二进制内容。
- 下载/上传成功后原子移动到正式目录。
- 记录 SHA256、文件大小、时长、容器和编码。
- 支持相同哈希文件去重；删除时检查是否被其他视频记录引用。
- 设置磁盘空间预警、单文件大小、单视频时长、并发下载数和用户存储配额。
- 备份说明必须覆盖数据库和媒体目录；只有数据库备份不能完整恢复视频库。

## 8. 技术架构与模块边界

### 8.1 推荐架构
- Frontend：React + TypeScript + Vite（最终按代码审查确认）。
- Backend：Python FastAPI。
- Database：SQLite，使用迁移工具和外键。
- Worker：独立任务进程，任务状态持久化。
- Network Acquisition：yt-dlp 作为外部工具/库调用，平台 Adapter 包装统一接口。
- Media Processing：FFmpeg/FFprobe。
- ASR：云端 Provider 抽象。
- LLM：云端 Provider 抽象。
- Storage：本地文件系统；未来可扩展 NAS/对象存储。
- Search：SQLite FTS5；向量检索为 P1。

### 8.2 模块划分
- `platform_adapters/`: BaseAdapter、BilibiliAdapter、DouyinAdapter；不直接处理 AI。
- `acquisition/`: yt-dlp 调用、元数据、字幕、媒体下载、退出码解析。
- `media/`: FFprobe、FFmpeg、音频切片、字幕轨道抽取、缩略图、关键帧。
- `storage/`: 文件命名、路径管理、哈希去重、保留与清理。
- `transcription/`: SubtitleProvider、ASRProvider、时间戳合并。
- `ai/`: LLMProvider、PromptRegistry、输出 Schema。
- `pipeline/`: 阶段编排、幂等、任务恢复。
- `repositories/`: 数据访问。
- `api/`: REST API。
- `web/`: 首页、详情页和交互。
- `observability/`: 错误码、任务耗时、费用和日志。

### 8.3 外部工具调用要求
- 使用参数数组调用子进程，不拼接 shell 命令字符串。
- 限定工作目录、输出路径、进程时长、CPU/内存、并发和文件大小。
- 对外部工具 stdout/stderr 做脱敏和长度限制。
- 校验输出文件确实存在、大小合理、可由 FFprobe 解析。
- 对下载 URL、重定向和网络访问做 SSRF 防护。
- yt-dlp/FFmpeg 版本需固定并记录；更新前跑回归样本。
- 不得把 Cookie、登录态、付费内容解锁参数作为常规配置。

| notes | id, video_id, chapter_id, start_ms, content, updated_at | 用户笔记 |
| processing_tasks | id, video_id, stage, status, progress, retry_count, idempotency_key, error_code, error_message, started_at, finished_at | 可恢复任务 |
| ai_usage_logs | id, task_id, provider, model, input_tokens, output_tokens, audio_seconds, cost, currency, created_at | 云端成本审计 |
| learning_progress | id, video_id, position_ms, duration_ms, last_watched_at, completed | 学习进度 |
| categories / tags | id, name, parent_id | 分类/标签 |

要求：
- `media_assets` 支持一个视频对应多个资产（原视频、音频、字幕、关键帧）。
- 路径使用受控相对路径，不接受任意客户端路径。
- 文件哈希用于去重；平台+平台视频 ID 用于来源去重。
- 所有时间统一毫秒。
- AI 内容保留 prompt、model、provider、输入哈希和生成时间。

## 11. 安全、隐私与版权要求

- 用户需确认有权下载、上传、转写和处理对应媒体内容。
- 不绕过 DRM、登录、付费、会员、验证码或反爬访问控制。
- 不使用或保存用户平台 Cookie 作为常规下载方案。
- SSRF：仅允许 http/https；拒绝 localhost、私网、链路本地和保留地址；DNS 解析与重定向逐次校验；限制跳转、超时、响应大小。
- 上传：限制扩展名、MIME、文件头、大小、时长；文件名随机化；禁止路径穿越。
- 子进程：参数数组调用、资源限制、工作目录隔离、禁止 shell 注入。
- API Key：只在服务端保存，日志脱敏，不进入仓库。
- 云端处理：告知用户会把音频/文本发送给哪个 ASR/LLM Provider；避免发送不必要的原视频。
- 保留与删除：用户可见、可配置；临时音频和失败任务残留要自动清理。
- 日志不记录完整字幕、密钥、Cookie 或不必要的个人内容。
- 部署需提供媒体目录与数据库备份恢复说明。

## 12. 非功能要求

- 文件处理异步化，Web 请求不等待整段下载/转码/ASR。
- 下载、FFmpeg、ASR 和 LLM 各自有并发、超时与重试限制。
- 任务 Worker 崩溃后可恢复，文件处理中间态可清理。
- 支持大文件分块上传或可恢复上传（可分阶段交付）。
- 媒体播放使用受控 Range 请求，支持拖动进度；不能把媒体目录作为静态公开目录。
- 支持桌面端优先，平板/手机可用。
- 存储空间不足时阻止新任务或暂停下载并明确提示。

## 13. 一期验收标准

### 13.1 导入与媒体资产
- B站/抖音 URL 能识别平台；能力不支持时给出明确原因。
- 对有权获取且技术路径可用的样本，能取得媒体文件；下载失败不伪造成功。
- 用户可上传至少一组常见视频、音频和字幕格式。
- 文件落库前通过 FFprobe 检查；文件大小、时长、哈希被记录。
- 重复上传/下载同一文件可通过哈希识别。
- 本地文件能在详情页播放并支持进度拖动。

### 13.2 字幕与转写
- 优先提取平台字幕或内嵌字幕轨道。
- 缺失/不完整字幕触发云端 ASR。
- ASR 分段时间戳正确映射回原视频时间轴。
- 字幕来源可区分，原始字幕不会被润色文本覆盖。
- 无法判定完整性的字幕标记为 unknown/partial。

### 13.3 AI
- 完整内容才标记完整总结。
- 部分转写只允许生成带范围说明的部分总结。
- 快速总结、深度总结、章节、知识点分别有可追溯的任务和模型记录。
- 技术总结包括原理、机制、实践、配置/代码、坑点；视频未涉及的内容不臆造。
- 时间戳来源可信，估算时间戳不能假装精准定位。

### 13.4 资源与安全
- 用户可设置媒体长期保留或处理后删除。
- 临时目录和临时音频可自动清理。
- 数据库和媒体目录可备份恢复。
- SSRF、路径穿越、命令注入、超大文件和恶意重定向测试通过。
- 不存在 Cookie/会员/DRM/访问控制绕过逻辑。

## 14. S0 必须验证的决策门

在承诺 B站/抖音网络下载前，逐平台用不需要绕过访问控制的合法样本验证：
1. 当前 yt-dlp 版本是否支持指定 URL 类型。
2. 元数据、字幕、完整媒体是否分别可用。
3. 失败是否因格式变化、区域、权限、登录、会员或技术错误。
4. FFmpeg 是否能处理下载结果，音视频流时长是否完整。
5. 字幕与媒体时间轴是否一致。
6. 相关工具的许可证和发行方式是否符合项目分发方式。
7. 记录版本、命令、样本类型、结果和限制；不把一次成功推广为全平台保证。

若某平台不能稳定、合规地下载，仍保留平台链接导入能力，同时支持用户上传有权使用的文件。该平台不能阻塞本地文件路线。

- V1.2：关键帧/多模态总结、双语字幕、全文检索增强、媒体批量管理。

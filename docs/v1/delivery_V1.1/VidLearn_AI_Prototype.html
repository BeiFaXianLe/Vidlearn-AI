核心内容总结

深度学习版
一句话概括
Redis 通过 RDB 快照和 AOF 命令追加两种机制实现数据持久化，分别在恢复速度、数据完整性和存储成本之间做权衡。

一、问题背景

Redis 主要基于内存提供高性能读写能力，但进程退出或机器故障会导致内存数据丢失。持久化机制用于将数据保存到磁盘，并在重启时恢复。

二、核心原理

1
RDB：定时生成数据快照在指定时机将内存中的数据集写入 RDB 文件。恢复速度快，文件紧凑，但两次快照之间可能丢失数据。
2
AOF：记录写命令将写操作追加到日志文件，重启时重放命令。数据丢失窗口更小，但文件可能更大，恢复耗时更长。
3
混合持久化结合 RDB 格式与 AOF 增量数据，兼顾加载速度与数据完整性，具体行为取决于 Redis 版本和配置。

三、关键配置示例

# AOF 持久化开关
appendonly yes

# 同步策略：每秒同步一次
appendfsync everysec

# RDB 快照规则示例
save 900 1
save 300 10
save 60 10000

四、实践建议与注意事项

  • 缓存型 Redis 与承载关键数据的 Redis，持久化策略不能一概而论。
  • 关注磁盘空间、重写期间资源消耗、备份恢复演练。
  • 不要只配置持久化而不验证恢复流程。

五、建议继续学习

建议进一步了解 fork、写时复制（COW）、AOF rewrite、fsync 策略，以及主从复制与持久化的边界。

04:18 RDB 本质上就是在某个时间点，对 Redis 当前的数据集做一次快照，然后把这个快照保存到磁盘文件中。

05:06 它的优点是文件比较紧凑，恢复速度也比较快，但是它不是实时的。

06:30 快照的触发时机由 save 规则决定，也可以手动执行 bgsave，后者会 fork 一个子进程来完成持久化。

16:20AOF 工作机制与 fsync 策略原理

16:20 AOF 以追加的方式记录每一条写命令，重启时通过重放命令来恢复数据。

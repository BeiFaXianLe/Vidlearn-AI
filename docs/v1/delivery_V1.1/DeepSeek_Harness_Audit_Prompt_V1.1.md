## 3. VidLearn AI 最新产品目标

VidLearn AI 是以本地媒体库为基础的个人视频学习平台：
- 一期来源：Bilibili、抖音网络链接，以及用户本地视频/音频/字幕文件。
- 通过 yt-dlp 等下载工具获取用户有权访问和处理的媒体；本地文件直接上传。
- 使用 FFmpeg/FFprobe 统一解析媒体、提取字幕轨道、音频和缩略图。
- 字幕策略：平台人工字幕/自动字幕/内嵌字幕/用户字幕优先；缺失或不完整时调用云端 ASR。
- AI 与 ASR 全部云端；本地负责任务、媒体存储、数据库和 UI。
- 默认保留本地视频文件，用户可以配置处理完成后删除。
- 视频详情页优先播放本地视频；本地媒体不可用时再尝试官方嵌入或原平台跳转。
- 必须检查字幕完整性；部分内容只能生成部分总结。
- 不绕过 DRM、会员、登录、反爬、验证码或其他访问控制。
- 页面原型已确认，不需要重新设计；审查重点是后端处理流程、媒体资产和工具复用。

## 4. 必须完成的审查项

### A. BiliSum 和 Muku 的代码审查
逐项追踪到真实实现：
- 视频 URL 解析、平台 Adapter、短链接处理和重定向。
- yt-dlp 调用方式、参数、安全边界、错误处理和版本约束。
- FFmpeg/FFprobe 调用方式、音频提取、字幕抽取、封面/关键帧。
- 下载文件是否保留、存储目录设计、临时文件清理。
- 原始字幕与 ASR 的优先级逻辑。
- ASR 音频切片、时间戳偏移、分段合并。
- AI 总结、章节、知识点和来源引用。
- Worker、任务持久化、重试、幂等、崩溃恢复。
- SQLite schema、迁移和媒体资产关系。
- 前端播放器是否播放本地文件、Range 请求如何实现。
- 安全、许可证、构建、测试和维护状况。

### B. yt-dlp 适用性审查
- 当前稳定版本与安装方式。
- B站和抖音 extractor 的实际代码位置和 URL 匹配规则。
- 元数据、字幕列表、人工字幕、自动字幕、视频/音频下载能力分别是什么。
- 不同 URL 类型是否需要登录或特定访问权限。
- 对短链、重定向、格式选择、断点下载、失败退出码的处理。
- 如何获取可供应用使用的结构化 JSON 元数据。
- 如何在不使用 Cookie、不绕过访问控制的条件下验证。
- yt-dlp 自更新/版本固定风险、依赖与许可证。
- 绝不将 extractor 存在视为某平台所有视频都可用。

### C. FFmpeg / FFprobe 适用性审查
- FFmpeg 构建选项与 LGPL/GPL/外部 codec 影响。
- FFprobe 是否能可靠获取时长、音视频流、字幕流、codec、分辨率。
- 提取字幕轨道的具体能力和格式限制。
- 音频提取、重采样、分段策略。
- 可播放格式与不支持/损坏/加密文件的失败表现。
- Windows/Linux/Docker 环境部署差异。
- 子进程资源和文件安全限制建议。

### D. 统一媒体处理流水线
验证以下架构是否合理并给出修改意见：

1. URL 安全校验和平台识别。
2. 元数据获取。
3. 字幕获取与媒体下载可并行执行。
4. 下载文件进入临时目录，FFprobe 验证。
5. 通过完整性校验后原子移动到媒体库；计算 SHA256。
6. 优先读取平台字幕或内嵌字幕轨道。
7. 字幕缺失/部分时 FFmpeg 提取音频并调用云端 ASR。
8. 合并字幕，检查时间轴、尾部截断和覆盖范围。
9. 生成快速总结、深度总结、章节和知识点。
10. 视频默认保留；用户可选择处理后删除；音频临时文件自动清理。

请评估每步失败恢复、幂等键、成本和中间数据存储。

- videos

- summaries
- chapters
- knowledge_points
- notes

### F. 完整性策略
设计媒体和字幕完整性状态：
- media_status：downloaded/uploaded/unavailable/failed/invalid
- transcript_status：complete/partial/missing/unknown/failed
- content_scope：full/partial/unknown

解释如何通过媒体时长、文件尾部解码、字幕时间戳、片段空洞、字幕来源判断完整性。不要仅以字幕条数或最后时间戳一个指标作绝对判断。部分内容只能生成部分总结。

### G. 安全检查
必须覆盖：
- SSRF、DNS rebinding、短链恶意重定向。
- URL 协议、私网 IP、超时、跳转次数和响应大小。
- yt-dlp/FFmpeg 子进程命令注入、参数注入、路径穿越。
- 文件扩展名/MIME/文件头混淆、压缩炸弹/超大媒体。
- 进程 CPU、内存、并发和运行时长限制。
- API Key、日志脱敏和云端数据传输告知。
- 媒体文件访问权限和 Range 播放接口。
- 下载和处理内容的授权边界。
- 任何 Cookie/DRM/会员/登录/反爬绕过实现都列为不可采纳项。

### H. 方案比较
评分 1–5 分（5 分最佳），加权：
- 与 VidLearn AI 产品形态匹配：15%
- 媒体下载/导入与存储架构：20%
- 字幕/ASR 流水线：15%
- Web 播放与学习工作台改造成本：10%
- 任务可靠性：10%
- 维护性与测试：10%
- 安全与合规风险可控：10%
- 许可证与分发灵活性：10%

比较：
1. Fork BiliSum。
2. Fork Muku。
3. 自建主体，复用 BiliSum 的知识处理模块、Muku 的媒体处理思路。
4. 完全自建，仅把它们作参考。

提供评分依据、置信度、未知项；不得因为 README 功能多就给高分。

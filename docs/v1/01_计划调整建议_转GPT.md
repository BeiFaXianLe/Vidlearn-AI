| # | 事实 | 对原计划的影响 |

| 1 | B站匿名**无平台字幕**（含自动字幕），两样本一致 | S2-04「字幕探测/下载」、S3-05「字幕优先级」在匿名下空转，需降级 |

## 二、建议对原计划的 8 处调整

### 调整 1｜S2 平台范围重排（工作量下调）
- 原：S2-05 Bilibili、S2-06 Douyin 都是一期 P0
- 改：**Bilibili 匿名 720P 为一期 P0**；**Douyin 降为 P2 / 占位**（保留 Adapter 接口 + 明确失败文案，不承诺）
- 收益：S2 省约 2–3 人日，且不再为"抖音可能失败"背风险

### 调整 2｜字幕策略改为「内嵌/用户字幕 → ASR」，删除"平台字幕优先"的默认路径
- 原：S3-05「按字幕优先级选取主字幕」（平台字幕排第一）
- 改：优先级 = ① 用户上传字幕 ② 视频内嵌字幕轨 ③ ASR；**平台在线字幕仅在 B 开关（登录态）下尝试**
- 同步改 PRD §5.3

### 调整 3｜S4 默认本地 ASR，云端降级为可选 Provider
- 原：S4 只接一个云端 ASR
- 改：`ASRProvider` 抽象下，**默认实现 = faster-whisper 本地**（CPU int8，small 起步，可配 medium）；云端作为第二实现
- 新增任务：S4-00 音频统一走 FFmpeg 解码为 16k mono PCM（规避 PyAV 兼容问题）

### 调整 4｜S3 增加"多指标完整性"明确任务
- 原：S3-02「媒体完整性校验、尾部解码检查」
- 改：拆成
  - 结构校验（ffprobe 能否解析、有无 moov）
  - 时长比对（容器时长 vs 视频流时长 vs 元数据时长，阈值可配）
  - 尾部解码（`ffmpeg -f null -` 退出码 + 最后 N 秒是否出帧）
  - 结论只能输出 verified/likely/partial/unknown

### 调整 5｜S6 播放器限定编码
- 新增：优先选 **avc1(H.264)** 流；hev1/av01 可能需要浏览器兼容处理或转码
- Range 播放接口必须支持拖动（验收 13.1 已要求）

### 调整 6｜验收标准修订（重要，避免验收即失败）
- 13.1 删去"1080P"表述，改为"匿名可取得的最高清晰度（实测 720P）"
- 13.1 抖音条款改为"仅保留导入入口与失败提示，不作为验收项"
- 13.2 字幕条款改为"无平台字幕时由本地 ASR 生成，时间戳可映射回原视频"

### 调整 7｜环境基线固定（写进 S1-01）
- Python **3.12**（uv venv）、yt-dlp **2026.10.26**、FFmpeg 8.1.1
- 依赖锁定：不依赖 faster-whisper 内置 PyAV 解码
- 若对外分发：FFmpeg 换 **LGPL build**（当前 full build 为 GPL）

### 调整 8｜B 开关（登录态）单独立项，不进一期关键路径
- 设计：本地存储、不外传、默认关闭、UI 明示风险、失败可降级
- 前置：需先修订 PRD §11 的 Cookie 条款

## 五、仍需你（或产品侧）拍板的 2 个点

1. **1080P 是否必须**？若必须，B 开关就要提升为一期 P0，并同步改 PRD §11 与合规说明。

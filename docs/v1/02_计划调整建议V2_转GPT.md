# VidLearn AI · 计划调整建议 V2（供 GPT 复审）

> 依据：`docs/evidence/S0_能力实测报告.md` + `docs/evidence/S0-B_登录态与抖音方案.md`
> 变更来源：用户确认「**允许使用登录态**」、要求「**B站不手动导入字幕**」「**抖音要保留**」
> 生成日期：2026-11-02

---

## 〇、一句话

V1 计划是按「匿名」推演的；现在改为「**登录态优先**」，这解锁了 B站 1080P + 平台自动字幕，同时抖音可以从占位恢复为一期功能——但**必须新增凭据管理与合规条款改写**，这是 V2 最大的结构性变化。

---

## 一、V1→V2 决策变更

| 项 | V1（匿名） | V2（登录态优先） |
|---|---|---|
| B站画质 | 720P 上限 | **1080P** |
| B站字幕 | 无，全靠 ASR | **平台字幕自动获取**（不手动导入） |
| 抖音 | 占位/不可用 | **保留，可下载** |
| ASR 定位 | 主路径 | **兜底 + 无字幕场景** |
| PRD §11 | 禁止 Cookie | **改：授权后本地加密保存、不外传、可删除** |
| 新增模块 | — | **CredentialProvider（凭据管理）** |

---

## 二、需要调整的 10 处

### 1. 新增「凭据管理」为 S1 一级模块（P0）
- `packages/credential/`：`CredentialProvider` 抽象
  - `none`（默认，匿名）
  - `bilibili_cookie`（扫码/导入/粘贴，本地加密）
  - `douyin_api`（对接自托管采集 API 的 base_url + key）
- 存储：本机加密（DPAPI 或 AES-GCM + 本地密钥），**不入日志、不入仓库、不外传**
- 生命周期：可一键清除；失效检测与重新登录引导
- 新增任务：S1-08 凭据加密存储与脱敏日志；S1-09 凭据失效检测

### 2. 字幕优先级重排（改 PRD §5.3 / S3-05）
```
① 登录态平台字幕（人工优先，AI 次之，标注来源）
② 视频内嵌字幕轨（FFmpeg 提取）
③ 本地 faster-whisper ASR
④ 云端 ASR（可选，长音频/高精度场景）
```

### 3. S2 改为双模式适配器（S2-03 起）
- `BilibiliAdapter`：`anonymous`（720P，无字幕）/ `authenticated`（1080P + 字幕）
- 请求头注入 cookie **只从 CredentialProvider 取**，绝不写死
- 失败分级：`need_login`（明确提示登录）/ `format_changed` / `network` / `not_authorized`

### 4. 抖音恢复为一期功能，但走「可选增强」路径（S2-06 重写）
- 方案 A（推荐，重）：`Evil0ctal/Douyin_TikTok_Download_API`（21k★, Apache-2.0）
  - **以独立服务形式对接**（docker compose / 本地 8000 端口），不内嵌源码
  - 通过 REST API 取元数据 + 无水印直链；其自带 offline transcriber 可复用
  - 需 PostgreSQL + Redis + Docker
- 方案 B（轻）：`jiji262/douyin-downloader`（12.5k★, MIT, Python）
  - 单条/批量下载、SQLite 去重，工程量小，先跑通再升级
- 统一 `DouyinAdapter` 接口，内部可切换 A/B
- UI 明示「第三方采集，合规风险自担」；失败降级为「保留元数据 + 提示上传本地文件」

### 5. S4 ASR 重新定位（工作量下调）
- 原：S4 是主路径，必须做切片/合并/完整性
- 改：**ASR 是兜底**。有平台字幕时直接跳过 ASR，节省成本
- 但**完整性判定仍为 P0**：平台字幕也可能只覆盖试看片段（S4-05 保留）

### 6. S3 增加「平台字幕标准化」
- 新增 S3-09：B站 JSON 字幕 → 统一 transcript_segments（毫秒时间戳）
- 注意 B站字幕 JSON 的 `body[].from/to` 单位是秒（浮点），需乘 1000 并做边界处理
- 多语言字幕（zh-CN / en-US / ai-zh）分别落 `source_captions`，不互相覆盖

### 7. 验收标准修订（13.1 / 13.2）
- 13.1：`登录态下可取得 1080P；匿名降级为 720P 并给出清晰提示`
- 13.2：`有平台字幕时优先使用并标注来源；无字幕或质量不足时触发本地 ASR`
- 13.1 抖音：`可通过自托管采集服务导入；不可用时给出明确降级提示`

### 8. 安全要求扩展（S8）
- 新增：凭据加密存储、日志脱敏、凭据泄露测试
- 新增：抖音采集服务是**独立信任边界**，需网络隔离/仅监听 localhost
- 新增：cookie 全链路不落盘明文（含临时文件、崩溃转储）

### 9. 风险表更新
| 新风险 | 等级 | 缓解 |
|---|---|---|
| 登录态失效/被封 | 中 | 失效检测 + 重新登录引导 + 匿名降级 |
| 凭据泄露 | 高 | 本地加密 + 不出网 + 日志脱敏 |
| 抖音采集服务合规 | 中高 | 默认关闭、UI 明示、仅个人自用、独立部署 |
| 平台字幕只覆盖片段 | 中 | 完整性判定，partial 只出部分总结 |
| 第三方项目失效 | 中 | Adapter 抽象 + 本地文件兜底 |

### 10. 人日调整
| 阶段 | 变化 |
|---|---|
| S1 | +1.5（凭据管理） |
| S2 | +2（双模式 + 抖音对接） |
| S4 | -1（ASR 降为兜底） |
| S8 | +1（凭据安全测试） |
| **合计** | 约 **41–66 人日**（V1 为 37–60） |
